# Haxe graphics API

The public Haxe graphics layer is intentionally split from the generated HXI
projection:

```text
Canvas -> CanvasCommandBuffer -> generated HXI -> nkui_* C ABI
```

Application code should use `Canvas`, `PathBuilder`, `Paint`, `Image`,
`FontCollection`, `TextLayout`, `DisplayList`, and `Renderer`. The command
buffer is an implementation detail and all UI resources are typed, idempotent
disposable objects. `UiError` is the single high-level error boundary.

The HXI remains a faithful ABI projection. Its calls are coarse and batched;
the generated byte-array slice companion submits a validated `Bytes` range
without copying the backing storage. Core declarations are supplied through
`@depends("NativeKit")`, not duplicated in the UI interface.

Regenerate and verify the UI interface with:

```sh
modules/ui/tools/check-hxi.sh
```

That command compares Linux, MinGW, Intel macOS, and ARM macOS Clang targets
under the `portable-abi64` contract before writing the canonical artifact.
The Haxeon UI showcase is the executable contract for paths, text, images,
transforms, clipping, layers, retained display lists, resizing, display scale,
zero-length submission, and stale-resource rejection:

```sh
modules/ui/tools/test-haxeon.sh
```
